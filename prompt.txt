Я хочу разработать приложение, которая будет осуществлять резервное копирование указанных директорий и файлов. Далее я указал его свойства в нескольких частях.

Часть 1. Краткая информация. 
Название проекта: KeepCopy.
Основанная задача: Для работы необходимо будет указать один или несколько источников, откуда нужно копировать, и директорию, куда будет производиться копирование. Копирование будет запускаться периодически в фоновом режиме в указанное время.
Целевая платформа: windows 10 и более.
Язык интерфейсов: русский.
Нефункциональные требования: 
●	Производительность: задачи на копирование и подсчет размера файлов должны выполняться в фоновом режиме без сильной нагрузки на компьютер, 
●	Поведение при ошибках: указанный файл пропускается, копирование продолжается. При этом название файла записывается в переменную и после завершения задачи при наличии таких ошибок в папке errors (создается, если нет) создается отдельный файл с timestamp (и суффиксом 001 и т.д.) и в нем указывается задача и перечисляются все пропущенные файлы (пример файла errors_28.06.2026_001). Такой файл создается отдельно на каждый запуск задачи. 
В файле логов создается одна строчка логов на каждый источник в каждой задаче. Результаты описаны в главе 7. Пример с ошибкой при копировании: «скопировано с ошибками (файл …)».
●	Автозапуск – программа должна запускаться с запуском системы (реализация в части 8).

Часть 2. Глоссарий. 
Задача – запланированное пользователем резервное копирование данных с различными настройками.
Фильтр или исключение – относительный путь до файла (файлов и директорий), выполненных в виде шаблона. Поддерживает символы, которые можно использовать в названиях файлов, слэши (для указания директорий), звездочка * (для указания любого количества символов) без пересечения директории и две звездочки ** - с пересечением (как glob). Используется для исключения файлов из операции копирования. 
Режим копирования – указывает на способ сохранения скопированных файлов.
След.вып. – дата (без времени) будущего запланированного запуска задачи; время задаётся отдельным полем. Обновляется только после автоматического запуска (включая догоняющий), вне зависимости от результата — в том числе при нехватке места. Ручной запуск След.вып. не меняет.
Послед.вып. – дата и время последнего запуска задачи. Обновляется при частичном, полном и ручном копировании, но не обновляется при полной ошибке (например, из-за нехватки места). Общий на всю задачу. Если в результате запуска в режимах «Сохранять изменения» и «Сохранять слоями» ни один файл не скопирован, значение все равно обновляется.

Часть 3. Краткое описание пользовательского интерфейса. Это должно быть оконное приложение. Современный дизайн. Светлая тема (по умолчанию). Имеется возможность изменять размер окна (протягиванием мыши), при этом сетка не должна ломаться. В качестве примера можешь ориентироваться на встроенный проводник Windows, filezilla.

Часть 4. Описание окон. В приложении должно быть реализованы несколько рабочих окон, но два основных: главное (таблица с задачами на копирование) и окно для создания таких задач.
Сетка не должна ломаться: layout адаптивный, таблица растягивается на доступную ширину. Минимальная ширина колонок — 50 px.
Векторные svg изображения – единообразные иконки 16×16.

Часть 4.1. Главное окно.
Главное окно имеет 3 зоны: toolbar (панель управления), таблица с задачами под ней и индикатор выполнения текущего задания (определение размера файлов или выполнение копирования) с указанием процесса (например, «Задача N: подсчёт / копирование (источник 2 из 3)»).
Размер – 60% от размера экрана, но не менее 800x600. 

Часть 4.1.1. Toolbar. Вверху располагается тулбар с четырьмя кнопками. Кнопки открывают новые окна (кроме кнопки Выполнить), при этом не являются выпадающими списками. 
Названия кнопок: 
●	Создать. При нажатии открывается окно Создание задачи.
●	Выполнить. При нажатии запускается выполнение задач на копирование. Никакие окна не открываются. Никак не влияет на расписание. Запускаются выделенные задачи (даже неактивные) или все активные, если никакая не выделена.
●	Настройки. При нажатии открывается окно с настройками.
●	Помощь. При нажатии открывается текстовое окно с инструкцией по работе программы.
При наведении мыши на вышеуказанные кнопки они должны слегка подсвечиваться или как-то выделяться.
Во время выполнения любой задачи кнопка Выполнить не работает и тухнет.
Часть 4.1.2. Таблица с задачами.
Под тулбаром размещается таблица во всю ширину рабочего окна. Таблица имеет вертикальный и горизонтальный scrollbar. В таблице будут указываться созданные пользователем задачи на выполнение резервного копирования нужных директорий. 
Столбики в таблице непостоянны, их отображение можно переключать в окне Настройки. Полный список столбцов: Название, Описание, Источники (исходная директория для копирования, их может быть несколько), Назначение (конечная директория для копирования), Время (в часах и минутах дня), «Период.» (периодичность – целое число дней), Исключения (может быть несколько, как и источников), Общий размер файлов (размер файлов по указанным источникам с учетом фильтров – о работе фильтров указано ниже, режим копирования не учитывается), «Послед.вып.» (дата и время последнего запуска, для новой задачи «—» и null в json, Обновляется при частичном, полном и ручном копировании, не обновляется при полной ошибке (например, из-за нехватки места)), «След.вып.» (дата предполагаемого будущего копирования без указания времени), Режим копирования (о режимах указано ниже), Сжатие (булевым значением: да / нет; выполняется ли сжатие в ZIP при копировании), Действия (особая колонка, которая всегда (без возможности отключения) находится в самом конце таблицы. В ней располагаются три кнопки: Активировать, Изменить и Удалить. Кнопки должны быть выполнены в виде векторных svg изображений плей (стрелочка вправо как в плеере), карандаша и красного крестика. При наведении мыши на кнопки они подсвечиваются). Кнопка активировать делает задачу активной (рабочей), повторное нажатие выключает задачу (она все еще существует, но не выполняется). Включенные задачи подсвечиваются. 
Подробнее про Источник. В колонке источник может быть указано несколько источников. В таком случае в задаче должен быть указан Один путь и справа от него +N, где N - количество источников за вычетом 1. При нажатии левой кнопкой мыши на задачу список раскрывается вниз и тогда каждый источник должен быть указан в отдельной строке внутри одной задачи. Список раскрывается только если есть +N у источников или исключений, иначе ничего не происходит. Повторный клик сворачивает задачу обратно. Разворачивание и сворачивание выполняется не мгновенно, а с легкой анимацией (но все равно быстро, например 0,5 секунды). 
Подробнее про Исключения. В колонке исключения аналогично может быть указано несколько фильтров, но в свернутом варианте - один +N, а в развернутом все построчно. 
Подробнее про След.вып. След.вып. может быть датой и пустым, если задача неактивна. Если задача неактивна, но периодичность и время указаны, то след.вып. отображается, но более тусклым цветом. След.вып. пустой только при очистке периода/времени в форме, а при выключении кнопкой — дата остаётся (тусклая).
Подробнее про колонки. Ширину колонок можно изменить при помощи мыши, что должно сохраняться в файле настроек программы. Строчки в таблице (задачи) нажимаемые, при нажатии выделяется (подсвечивается) вся строчка и раскрывается список источников или фильтров при наличии. 
Порядок колонок не изменяется и установлено в перечислении выше.
Подробнее про кнопки. Кнопки активации, изменения и удаления нажимаемые. При нажатии на кнопку изменить открывается окно Создание задачи в режиме изменения. В таком режиме это окно должно быть заполнено в соответствии с указанной задачей и должно хранить ссылку на существующую задачу так, чтобы изменять именно ее, без создания новых задач. Кнопка Удалить удаляет указанную задачу. При нажатии Удалить появляется подтверждение.
Двойной клик по строке ничего не делает.

Часть 4.2. Окно Создание задачи.
Состоит из трёх слегка разделённых блоков: Описание, Исключения, Дополнительно. В самом низу окна по центру находится кнопка Сохранить.
Всё окно преимущественно вертикально ориентированно. Заполняемые поля следуют один за другим вертикально, название полей в отдельных строчках.
Заголовок окна меняется в зависимости от режима: «Создание задачи» / «Редактирование: Задача 1» (Режим создания vs редактирования).

Часть 4.2.1. Блок Описание.
Перечень полей ввода: название, описание, источник, назначение, время, периодичность. 
Название – обязательное поле в одну строчку. В нём должно стоять значение по умолчанию, равное «Задача N», где N – следующий номер. Например, если уже имеется «Задача 1», то значение по умолчанию будет «Задача 2». Номер последней задачи не запоминается, а определяется перебором прохождением по списку задач.
Описание – необязательное текстовое поле высотой в три строчки. При переполнении появляется вертикальный scroll.
Источник – обязательное поле для указания адреса директории, откуда будет производиться копирование. Ввести путь можно вручную или при помощи кнопки выбрать. При нажатии на кнопку открывается диалоговое окно системы для указания директории или файла. После завершения ввода (смена фокуса) обязательно должны быть проверены две проверки: на существование, а также на валидацию (в пути разрешены только определенные символы). Если человек указывает неверный слэш (/ и \), то неверные должны быть автоматически заменены на верные в данной системе. Путей-источников для копирования может быть несколько. Рядом с окном и кнопкой ввода располагается svg элемент плюсик. При нажатии путь сохраняется в read only табличку ниже. В указанной табличке каждый путь указан в отдельную строчку, справа имеется крестик для удаления, высота всегда 3 строчки, имеется горизонтальный и вертикальный скролл. 
В задаче должен быть как минимум один источник, иначе ошибка валидации. Дубликаты не сохраняются. 
Назначение – обязательное поле для указания адреса директории, в которую будет производиться копирование. Ввести путь также можно вручную или при помощи кнопки выбрать. Путь также должен быть проверен на существование и провалидирован. Изначально указанный путь назначения должен существовать, но при копировании могут быть созданы новые директории для хранения файлов. Файловая структура должна соответствовать исходной. Для разных задач, вероятно, будет указан один путь назначения. Для каждого пути-источника в «Назначение» создаётся подпапка с именем последнего компонента пути (C:\Users\Engineer Paul\Desktop\Python_temp → Python_temp; для одиночного файла C:\data\report.txt → report.txt). Файлы каждого источника копируются только в «свою» подпапку. Структура внутри повторяет структуру относительно корня источника (для одиночного файла — файл лежит непосредственно в этой подпапке).
Время – необязательное поле для указания системного времени (может быть пустым), в которое будет производиться копирование. Указывается часы и минуты без секунд. Ограничение от 0 до 23:59. Значение по умолчанию 00:00. Пустое поле = явная очистка поля.
Периодичность – необязательное целочисленное поле (может быть пустым), указывающее с какой периодичностью в днях должно производиться копирование. Ограничения от одного до 366. Необязательное поле, значение по умолчанию 7. Периодичность указывает сколько каждые N дней должно выполняться копирование. Не зависит от фактического выполнения копирования (которое может быть ручным), а только от последней запланированной даты (След.вып.). Значение 7 означает, что каждые 7 дней в указанное время. Пустое поле = явная очистка поля.

Часть 4.2.2. Блок Исключения.
Фильтры-исключения – это дополнительные условия для исключения файлов и папок из операции копирования. По сути исключение также представляет собой часть пути со всеми ограничениями на валидацию символов. Однако оно дополнено символом звёздочка * или **. Символ * будет означать любое количество знаков и символов без пересечения директорий, а ** - с пересечением. Также в исключении разрешено использование слэшей для указания перехода по директориям (неверный слэш разрешен, но автоматически заменяется на правильный для данной системы при сохранении). Например, фильтр «**.png» (без пробелов) исключает все картинки формата PNG во всех под директориях в указанном пути копирования. А исключение */* или *\* исключает все файлы в поддиректориях 1 уровня. На одной задаче может быть установлено любое количество фильтров. 
Исключение проверяется относительно корня того источника, в котором найден файл. Один и тот же шаблон *.tmp действует для всех источников одной задачи.
По умолчанию копируются все файлы из всех источников (с учётом max size). Файл не копируется, если его относительный путь совпадает хотя бы с одним исключением. Порядок исключений в таблице не важен. Совпадение: шаблон с * сопоставляется с относительным путём от корня того источника, внутри которого лежит файл.
Визуально в окне программы в категорию исключения входят: 
текстовое поле для ввода фильтра высотой в одну строчку, 
справа в той же строчке располагается кнопка создать, которая выполнена в виде векторной svg изображения плюсика. 
Ниже располагается таблица со всеми созданными фильтрами, аналогично таблице путей-источников. Её размер четыре строчек с учетом заголовков, имеет вертикальный (и при необходимости горизонтальный) скролл. 
При попытке создать два одинаковых исключения второй экземпляр (дубликат) создаваться не должен.

Часть 4.2.3. Блок Дополнительно. 
В отличие от других разделов здесь название каждого поля и его поле ввода будут располагаться в одной строчке.
Первое поле – максимальный размер файлов. Здесь пользователем указывается максимальный размер копируемых файлов в мегабайтах. Это поле необязательно. В дальнейшем при копировании и подсчёте размеров копируемой области файлы с более большим размером должны игнорироваться (>, а не >=). Поле может быть пустым, что является значением по умолчанию.
Второе поле – Сжатие (в таблице задач отображается как колонка «Сжатие»). Поле ввода – логический чекбокс. Значение по умолчанию ложь (выключено). При включении задача выполняет копирование со сжатием в ZIP. Формат сжатия – zip. Степень сжатия 5 из 10. Для каждого источника создаётся отдельный ZIP с именем последнего компонента пути источника (any1.zip, any2.zip — по тем же правилам, что и имена подпапок). При наличии нескольких источников в папке назначения создаётся несколько ZIP (отдельно на каждый источник).
Третье поле – Режим копирования. Поле ввода – выпадающий список из трёх значений: 
1.	Сохранять изменения (по умолчанию). В результате выполнение задачи копируются только новые и изменённые (с более новой датой изменения, чем послед.вып.) файлы. Копирование происходит в одну и ту же директорию с заменой измененных файлов. В случае активного сжатия, новые файлы добавляются к существующему ZIP с заменой файлов при копировании (в данном режиме по одному zip на источник).
Пример: источники – D:\sources\any1 и D:\sources\any2, вставка – D:\dest. Результат: D:\dest\any1 и D:\dest\any2. Результат со сжатием: D:\dest\any1.zip и D:\dest\any2.zip.
2.	Сохранять слоями. Новые и изменённые файлы копируются в новую директорию, таким образом в результате выполнения задачи каждый раз будет создаваться новая дополнительная директория. Название backup_28.06.2026_001 (название папки как обычно с датой и номером для разных слоев) (директория или ZIP). Т.е. при копировании создается целевая папка, как и ранее, но ее содержимое будет располагаться в backup слоях (при включённом сжатии слой — это backup_28.06.2026_001.zip). Суффикс 001 создается для каждой следующей вставки (для каждого запуска), если обнаружены новые файлы (пустую папку не сохраняем). Счётчик _001 растет для каждого источника на каждый запуск с одинаковой датой, сбрасывается для новой даты (он нужен, чтобы не было конфликта имен для нового слоя). Получать новое значение сканированием директории назначения. 
Не создавать каталог слоя backup_..., если нет файлов для копирования; пустые внутренние каталоги внутри слоя — по правилам 5.4.
В каждый новый слой попадают только те файлы и папки, чьи даты и время изменения > послед.вып. (или абсолютно все, если послед.вып. отсутствует).
Пример: источники – D:\sources\any1 и D:\sources\any2, вставка – D:\dest. Результат: D:\dest\any1\backup_28.06.2026_001, D:\dest\any1\backup_28.06.2026_002 и D:\dest\any2\backup_28.06.2026_001, D:\dest\any2\backup_28.06.2026_002. Результат со сжатием: D:\dest\any1\backup_28.06.2026_001.zip… (аналогично примеру без сжатия).
3.	Дублирование. В результате выполнения задачи происходит полное копирование всех файлов в новую директорию. Работает полностью аналогично режиму 2, но с полным копированием файлов. Таким образом, как и в предыдущем режиме у нас будет создаваться новая директория при каждом выполнении задачи. Т.о. поведение – как в предыдущем случае, но в предыдущем случае в директорию копируются только новые изменённые файлы, а в данном режиме абсолютно все файлы. Т.е. выполняется полное копирование всех запланированных файлов в разные слои backup_. Новый слой создается даже если файлы не изменились.
Пример: источники – D:\sources\any1 и D:\sources\any2, вставка – D:\dest. Результат: D:\dest\any1\backup_28.06.2026_001, D:\dest\any1\backup_28.06.2026_002 и D:\dest\any2\backup_28.06.2026_001, D:\dest\any2\backup_28.06.2026_002. Результат со сжатием: D:\dest\any1\backup_28.06.2026_001.zip… (аналогично примеру без сжатия).

Часть 5.3. Алгоритм поиска и подсчета
Придумай оптимальный алгоритм поиска файлов внутри указанных в задачах путей с учетом исключений. При копировании сначала должен исчисляться размер файлов, которые нужно скопировать (с учетом путей, фильтров, ограничения максимального размера и даты послед.вып.), далее должна выполняться проверка, что на диске достаточно места для вставки скопированных файлов (с запасом 10% от требуемого объема), после чего выполняется копирование.
Примерный алгоритм поиска файлов:
●	Обход os.walk или pathlib.rglob от источника,  используй glob (для одного файла обход дерева не подходит, один файл копируется как единственный элемент), 
●	Для каждого пути — относительный путь от источника, алгоритм рассматривает только файлы и директории, указанные в пути на копирование.
●	Применить фильтры (при исключении папки исключаются все файлы и папки внутри нее)
●	Отфильтровать по max size
●	Для режима «Сохранять изменения» и «Сохранять слоями» — сравнить даты и времени изменения файлов с послед.вып. (копировать все, если послед.вып. отсутствует). Для дублирования сравнение не происходит.
Расчёт След.вып. (формула 5.3 — для активации, редактирования и после автоматического запуска; при первом создании задачи см. ниже): без циклов и рекурсии. Разность между текущим днём и днём След.вып., целочисленно делим на период, добавляем 1 и умножаем на периодичность — получаем следующую дату. Если сейчас < След.вып. + время, пересчёт не нужен.
Задача запускается автоматически, когда сейчас ≥ След.вып. + время (время из поля задачи).
Часть 5.4. Поведение программы
Дополнительные поля. Дополнительно к указанным выше полям у каждой задачи также должны быть добавлены дата создания и состояние активности is_active (true / false). 
Активность задачи. Планировщик запускает только активные задачи.
По умолчанию задача активна, если указаны периодичность и время (на основе периодичности вычисляется След.вып.) (время 00:00 и периодичность 7 (значения по умолчанию) считаются указанным). При выключении задачи ее след.вып. и время сохраняются (замораживаются), задача становится неактивной. При активации задачи ее след.вып. вычисляется заново по формуле 5.3 с использованием сохраненного След.вып. (ручной запуск расписание не меняет). След.вып удаляется при удалении периодичности или времени в режиме редактирования (может стать пустым), что также соответствует выключению задачи (is_active = false в JSON). Если указать периодичность и время у неактивной задачи, то она не станет активной автоматически, для этого ее нужно будет включить вручную. При включении след.вып. обновляется, у неактивной задачи он не обновляется автоматически, но обновляется при редактировании задачи (если указаны периодичность и время) по формуле 5.3 (вместе след.вып. используется послед.вып. или дата и время создания). Сохранение отредактированной задачи не меняет is_active, кроме случая очистки периода/времени (is_active = false).
Подсчет размеров. Подсчет размера файлов должен выполняться при запуске программы в отдельном потоке и при выполнении задач. При запуске программы текущее значение должно браться из кэша (общего файла настроек) и подсвечиваться. После пересчета значение обновляется, а подсвечивание пропадает. 
Параллельность. Задачи копирования и подсчета размеров должны выполняться параллельно основному потоку программы (не блокирует UI). Если уже запущен подсчет размера, то копирование ожидает его завершения. Копирование выполняется только после завершения подсчета размеров. Задачи на подсчет и копирование выполняются последовательно, при этом перед выполнением каждой конкретной задачи должен быть завершен новый подсчет размера файлов.
Ручной и автоматический запуск: задачи в очереди, по одной; подсчёт размеров текущей задачи → копирование → следующая. UI не блокируется (работа в фоновых потоках). Слово «параллельно» = не блокирует главное окно, а не одновременный запуск всех задач.
Условия копирования. Копируются все файлы и директории, соответствующие условиям (включая пустые каталоги). Каталог слоя backup_... не создаётся, если нет ни одного файла для копирования (см. режимы в 4.2.3). Файлы, удалённые в источнике, в назначении не удаляются.
Дата копирования. При создании задачи с указанными периодичностью и временем: След.вып. = дата_создания + N дней (N — периодичность); первый запуск в день создания не производится. Если периодичность или время пустые — задача неактивна (is_active = false, След.вып. = null). При активации и редактировании — формула 5.3. Пример: создание 28.06, период 7, время 14:00 → След.вып. = 05.07.
После каждого автоматического запуска (включая догоняющий) След.вып. пересчитывается по формуле 5.3.
Очевидно, что программа может быть запущена после даты запланированного в задачах копирования. Чтобы не пропускать, при запуске должна быть совершена проверка, наступило ли нужное время для копирования. Если да, то выполнить копирование через 5 минут (чтобы не перенагружать компьютер при запуске). «След.вып.» всегда вычисляется по формуле из 5.3 от последнего След.вып., а не создания или текущего (ручного) задачи; догоняющий запуск обновляет След.вып. 
Таким образом, при пропусках задач их необходимо догонять, при наличии нескольких пропусков выполняется только один прогон (не несколько). 
Дата следующего выполнения задачи не зависит от фактического, а зависит от След.вып.. Если задача неактивна, то «След.вып.» может быть пустым или по-прежнему существовать (но не работать). При активации задачи вычисляется ее «След.вып.» на основе сохранённого След.вып. по формуле 5.3; если след.вып. не указан, то он определяется по формуле 5.3 с использованием послед.вып. (или даты создания) вместо след.вып..
Для определения момента запуска планируемая дата (След.вып) объединяется с временем и сравнивается с сейчас. Далее время не меняется, а След.вып обновляется на новое значение. Новый След.вып. определяется после выполнения задачи вне зависимости от её результата, но только при автоматическом запуске (ручной След.вып. не меняет). Послед.вып. при этом следует правилам глоссария (не обновляется при полной ошибке, например нехватке места).
Поведение с защищенными файлами. Если нет прав на чтение/запись или файл занят другим процессом — пропуск файла. В логах указать, что копирование частичное. Пропущенные файлы указываются в отдельном файле с timestamp. 
Длинные пути Windows (>260) — поддерживать.
Сохранение настроек. Вся сохраненная в процессе работы программы информация о настройках должна сохраняться в settings.json. Но внутри файла для разной информации желательно создать разные переменные (структуры). Это обеспечит читаемость и не будет плодить большое количество вспомогательных файлов.
Папка errors. При создании файлов errors_<timestamp>_001 (без времени) (при неудачных копированиях) должна создаться отдельная папка errors (если еще не создана) и данные файлы сохраняются в нее. То же самое описано в части 1.
Индекс инкрементируется (_002, _003 и т.д.) при каждом отдельном запуске задачи с ошибками (суффикс уникален в пределах одной задачи; при каждом запуске с ошибками — +1).
Нехватка места. При нехватке места выполнение задачи отменяется; в логах — ошибка «недостаточно места на диске»; файл errors не создаётся. След.вып. обновляется (автозапуск); Послед.вып. — нет. Повтор — только вручную.
Часть 5.5. Ограничения
Данная программа никак не должна влиять на копируемые файлы. Только Read-only копирование. Запрещено удаление, shutil.move, изменение mtime и другие изменения источника.

Часть 6. Тесты.
В проекте должны быть тесты только на pytest. Тесты будут создавать задачи и выполнять их, при этом реально должны быть созданы маленькие файлы и директории и проверяться их конечное копирование. После копирования все тестовые файлы и директории удаляются. Создание и копирование должно происходить в директории рядом с проектом. Тесты без gui, только сервисы. 
Начальный перечень тестов (можешь дополнить своими):
1.	Копирование без фильтров, режим «Сохранять изменения», повторный запуск — только новый файл,
2.	простой фильтр,
3.	Фильтр с *
4.	Фильтр с **
5.	Max size — большой файл пропускается (при размере файла равном указанному он разрешается),
6.	Режим «Сохранять слоями». Один источник, запуск, изменение файла, повторный запуск – 2 слоя, во втором слое только измененные файлы.
7.	Режим «Дублирование». Один источник, запуск, изменение файла, повторный запуск – 2 слоя, во втором слое все файлы.
8.	Недостаточно места — ошибка, исходник не тронут.
9.	Сжатие — zip создан, содержимое проверено.
10.	Несколько источников. 
11.	Добавление изменений в существующий zip («Сохранять изменения» + сжатие + несколько источников). 
12.	Неактивная задача пропускается планировщиком
13.	Неактивная задача запускается вручную

Часть 7. Логирование.
Выполнение задач должно логироваться в отдельный текстовый файл рядом с проектом. Файл должен быть читаем для человека. Текст каждого лога не должен превышать одной строчки. В тексте указывается текущие дата и время, задача, исходная директория, описание задачи до 100 символов (если больше, то ставится многоточие) и результат (успешно | ошибка | скопировано с ошибками (файл errors_28.06.2026_001)). Максимальный размер файла – 1000 строчек, при превышении самые ранние логи удаляются.
Пример логов:
2026-06-28 14:30:05 | Задача 1 | C:\Data | Ежедневный бэкап документов... | успешно
2026-06-28 14:30:05 | Задача 1 | C:\Data | Ежедневный бэкап документов... | скопировано с ошибками (файл errors_28.06.2026_001)
2026-06-28 14:30:12 | Задача 2 | D:\Photos | Ежедневный бэкап документов...  | ошибка: недостаточно места на диске
Кодировка логов: UTF-8
Имя файла: backup.log
Ротация: ровно 1000 строк = 1000 записей (один лог должен помещаться в одну строку).
При пропуске файлов по фильтру и size ничего не делать.
При наличии нескольких источников в одной задаче создается несколько независимых логов. При ошибке из-за нехватки места создается отдельный лог на каждый источник. 
При пропуске файлов (ошибках при копировании) создается отдельный файл с timestamp без времени (errors_<timestamp>_001). Файл создается отдельно на каждую запущенную задачу копирования (все источники в один файл). В файле сначала указывается вся информация о задаче. А потом построчно указываются файлы, которые были пропущены в результате какой-то ошибки. Справа от адреса файла – текст ошибки. 
Если ошибок при копировании не было, но при копирования фактически не было скопировано ни одного файла (нет изменений, не прошли фильтры и др. причины) логирования успешного копирования все равно происходит.
